What changed, and why

The surface is intentionally narrow: it is a current client-presence report for owner support and adoption decisions, not a replay or broad behavioral analytics dashboard.

Generic usage counts became named client context

Was

Aggregate usage could show activity volume, but not which user, device, OS, build, or distribution channel was behind it.

Now

Each visible roster user has an app-use state and last launch, plus every reported iOS/web installation with coarse device identity, OS version, marketing version, build, release channel, first/last seen, and last opened timestamps.

Build freshness became an explicit support signal

Was

A developer had to infer whether a client was stale from separate release and user information.

Now

The report compares iOS builds to configured IOS_LATEST_APP_VERSION / IOS_LATEST_APP_BUILD and labels them Latest, Stale, Newer, or Compare unavailable.

The report stays private and privacy-light

Was

A role-only report would expose named adoption detail too broadly, and hardware identifiers could become a fingerprinting surface.

Now

The route is owner-allowlisted, hidden roster users are excluded, the installation key is HMAC-scoped server-side, and only coarse device metadata is retained.
